# Exploring the Use of Electron in WebAssembly

A proof of concept bringing Electron to WebAssembly Text (WAT) with a minimal JavaScript footprint.

The project itself is simple: create an Electron window and load a URL when the app is ready. In plain old JavaScript, this takes only a few lines of code. In [src/index.wat](src/index.wat), however, the same task becomes surprisingly complex when written in WebAssembly Text.

## JavaScript Interop

Before we get into the WAT, let's take a look at [src/index.mjs](src/index.mjs):

```js
const wasm = fs.readFileSync("index.wasm");
const imports = Object.assign(globalThis, electron);
await WebAssembly_instantiate(wasm, Object(imports), { importedStringConstants: "" });
```

The core JavaScript is remarkably small, consisting of just three lines:

1. Load the Wasm binary generated by `wat2wasm`.
2. Build the imports object by merging `electron` into `globalThis`, allowing native JavaScript and Electron APIs to be used simultaneously.
3. Pass the Wasm binary and imports to `WebAssembly.instantiate` to run the module. The `importedStringConstants` compile option enables string constants to be embedded directly in the WebAssembly Text.

For JavaScript interop, this is as minimal as it gets.

## WebAssembly Text

Now, let's look at the [src/index.wasm](src/index.wasm):

```wasm
    (import "" "constructor" (global $constructor externref))
```

Here, we declare a global `$constructor` with the string constant `"constructor"`. Without the `importedStringConstants` option, the module would fail to compile.

We could instead import the strings from JavaScript, but that would undermine the goal of keeping much of the implementation in WAT.

Next, we import functions:

```wasm
    (import "app" "whenReady"
        (func $app.whenReady
            (result externref)))
```

These imports specify the function's parameters and return value. In this case, Electron's `app.whenReady()` takes no arguments and returns a `Promise`, represented here by `externref`.

Among the imports, you may see something like this:

```wasm
    (import "BrowserWindow" "prototype"
        (global $BrowserWindow.prototype externref))
```

Unlike the function imports, this import provides a global value, similar to a string constant import. Here, the global `$BrowserWindow.prototype` refers to `BrowserWindow.prototype` in JavaScript.

We use it to access properties of `BrowserWindow.prototype`, such as `constructor`:

```wasm
        (global.get $BrowserWindow.prototype)
        (global.get $constructor)
        (call $Reflect.get)
```

This is equivalent to the following JavaScript:

```js
        Reflect.get(BrowserWindow.prototype, "constructor")
```

But why not just import `constructor` directly?

```wasm
    (import "BrowserWindow" "prototype" "constructor"
        (global $BrowserWindow.prototype.constructor externref))
```

This doesn't work because WAT imports only support a module name and an import name; they cannot traverse nested JavaScript properties.

Instead, we import JavaScript's native `Reflect.get` and use it to access properties such as `constructor` from `BrowserWindow.prototype`.

Because of this, logic that is trivial in JavaScript requires significantly more boilerplate in WebAssembly Text.

## The Rest of the WAT

WebAssembly Text is a complex language, so this write-up only provides a brief overview of the code. Explaining every line in detail would be enough material for a book. The rest of the WAT is commented, with most comments following this format:

```wasm
        (call $app.whenReady)
        (local.get $args)
        (call $Reflect.apply) ;; app.whenReady().then(...$args)
```

The comments correspond to their JavaScript equivalents, making the WAT easier to understand by relating it to familiar JavaScript code.

For more information, refer to the links provided in [References](#references). WebAssembly Text is still a relatively new technology, so some of the information above may become outdated over time.

## Usage

Requirements:

- [Node.js](https://nodejs.org)
- [wat2wasm](https://github.com/WebAssembly/wabt/releases)

1. Clone the repository:

    ```sh
    git clone https://github.com/pseudoical/electron-wasm.git
    ```

2. Install dependencies:

    ```sh
    npm install
    ```

3. Run the project:

    ```sh
    npm start
    ```
